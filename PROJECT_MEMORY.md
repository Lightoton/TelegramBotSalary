# Память Проекта: TelegramBotSalary (Auto-Memory)

## 1. Суть проекта и текущий прогресс
**Суть:** Разработка Telegram-бота для учета доходов и расходов фрилансеров/самозанятых. Бот позволяет гибко настраивать услуги (процент с чека), фиксировать почасовую работу, рассчитывать налоги, вести умный расчет бюджета "На жизнь" (аренда, еда, доп. траты) и архивировать закрытые месяцы для защиты данных.
**Прогресс:** Проект полностью готов к использованию и выложен на GitHub (`Lightoton/TelegramBotSalary`). Версия 1.0 стабильна. Написана подробная двуязычная документация, добавлены тесты (Jacoco), внедрена система онбординга с секретным паролем, добавлена расширенная логика работы с нецелыми числами. Последняя добавленная фича: отображение общей суммы заработанного за день в детальной статистике.

## 2. Стек технологий и архитектура
*   **Язык:** Java 21
*   **Фреймворк:** Spring Boot 3
*   **База Данных:** PostgreSQL (для продакшена) / H2 (для тестов и локальной разработки)
*   **Telegram API:** `telegrambots-spring-boot-starter` (LongPolling)
*   **Инфраструктура:** Docker & Docker Compose
*   **Архитектурные решения:**
    *   `UpdateHandler` — центральный маршрутизатор сообщений и состояний бота.
    *   `CalculationService` и `BudgetService` — сервисы бизнес-логики.
    *   `KeyboardUtils` — генерация Inline и Reply клавиатур для UI.
    *   Управление состояниями пользователя (FSM) реализовано через Enum `BotState` (напр. `AWAITING_PASSWORD`, `MAIN_MENU`).

## 3. Важные технические нюансы и костыли
*   **Окружение пользователя:** Windows. Путь к проекту: `C:\Users\light\Desktop\TelegramBotSalary`.
*   **Безопасность БД (Важно!):** В `docker-compose.yml` убран проброс порта `5432:5432` наружу, чтобы избежать уязвимости и сканирований извне (по запросу CERT-Bund). Приложение и БД общаются строго внутри сети Docker по хосту `postgres:5432`.
*   **Парсинг чисел (Костыль):** При вводе денежных сумм пользователи могут использовать как точку, так и запятую. Перед парсингом `BigDecimal` везде внедрена замена: `text.replace(",", ".")`.
*   **Онбординг и авторизация:** При первом запуске требуется ввести `bot.admin.password` (из `.env`).
*   **Логика лимитов "На жизнь":** По умолчанию в БД лимиты на Аренду, Еду и Допы равны `-1`. Это работает как триггер: при первом нажатии на кнопку "На жизнь" бот просит пользователя их настроить. ВАЖНО: Раздел расходов находится именно в кнопке "На жизнь", а не в "Настройках".
*   **Конфигурация:** Ожидается наличие файла `.env` с переменными: `TELEGRAM_BOT_TOKEN`, `TELEGRAM_BOT_USERNAME`, `bot.admin.password`. В репозитории хранится только очищенный `.env.example`.
